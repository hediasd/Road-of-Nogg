# Nogg Herald -- pixel glyph source (display face).
#
# Source of truth. The PNG atlas, the specimen sheet, and the FontFile beside
# it are BUILD OUTPUTS: regenerate with
#
#   Godot_v4.4-stable_win64.exe --headless --path . --script res://scripts/bake_herald_font.gd
#
# Never hand-edit the outputs; edit a glyph here and re-bake.
#
# --- The grid -------------------------------------------------------------
#
# 13 rows tall. Width is PER GLYPH -- this face is proportional, which is the
# whole difference from Nogg Terminal.
#
#   row  0      dot row: the tittle of `i`, and headroom for accents
#   rows 1-8    cap / ascender band (cap height 8)
#   rows 3-8    x-height band (x-height 6)
#   -- baseline sits immediately below row 8 --
#   rows 9-10   descender band (descender 2)
#   rows 11-12  bottom leading
#
# Ascent 9 + descent 4 = 13, the line height the reference art actually sets.
#
# --- The style rules ------------------------------------------------------
#
#   1. VERTICAL strokes are two pixels. HORIZONTAL strokes are one. This is the
#      face's whole character and the easiest rule to break by accident: a
#      uniformly two-pixel face looks fat and squat, not bold and tall. Every
#      bar, shoulder, crossbar, and terminal is one pixel; every stem is two.
#   2. Round letters are octagons: corners clipped exactly one pixel. There are
#      no curves in this font, only clipped corners -- the same rule Terminal
#      obeys, so the two faces look related when stacked.
#   3. Terminals are flat and grid-aligned.
#   4. Diagonals are single-pixel staircases even though stems are two, because
#      a two-pixel staircase at this size reads as a blob.
#   5. Counters are two pixels wide where the width allows it. `a` and `r` are
#      narrow enough that they close to one; that is deliberate and matches the
#      reference, not an oversight.
#
# --- The format -----------------------------------------------------------
#
# `@ <hex codepoint> <label> w=<width>` opens a glyph; the next 13 lines are
# its rows, each exactly <width> characters. `#` is ink, `.` is empty.
# `& <left> <right> <delta>` declares a kerning pair, written with literal
# characters because pair values are the part of this face a human revisits.

# --- Pair values ----------------------------------------------------------
#
# Measured, not invented. Segmenting the reference art into ink runs shows
# `St`, `af`, `of`, and `ry` merging into single runs at a gap of ZERO -- the
# letters touch, they do not overlap. Only `ff` genuinely overlaps: `a` is 5
# wide and `f` is 5, yet the run "aff" measures 14, which is one pixel short of
# touching twice.
#
# So the bleed is mostly the two one-pixel OUTLINES meeting at gap zero, not
# ink crossing ink. That is why -1 is the standard value here and -2 is rare:
# an earlier draft used -2 throughout and the words turned to mush.
#
# The rule a pair must satisfy: the leading glyph has to leave the arriving one
# somewhere empty to sit. `F` fails it -- its arms run the full width of its box
# at rows 1 and 4, so an `l` pulled in welds to both and "Flute" reads as
# "Aute". Verified by rendering, and the reason `F l` is absent.

# This table is short on purpose. An earlier draft had 27 pairs invented from
# impressions, and measuring the reference killed most of them: it sets
# "Sarana" with `r` and `a` as separate runs, "Lake" with no welds at all, and
# "Up" open. Welding those made words measure 23 where the reference sets 26.
#
# Every pair below is one the reference art actually merges into a single ink
# run, with one named exception.

# `f` is the welding letter. Its crossbar occupies row 3 alone, so whatever
# arrives beside it has the whole of rows 4-8 free to sit in.
& a f -1
& o f -1
# The one true overlap in the face: `a` is 5 wide and `f` is 5, yet the run
# "aff" measures 14 -- one pixel short of touching twice.
& f f -2

# A cap arm over a short following letter. `S` closes its bottom curve at row
# 8, leaving rows 1-2 open for the `t` ascender.
& S t -1

# `r` has nothing under its arm, so a descending letter tucks beneath it.
# Measured in "Dry"; note it does NOT apply to `r a`, which the reference
# leaves open.
& r y -1

# The pair that started this, and the only one here not measured from the
# native-resolution art -- it comes from "Light" and "Right" in the scaled
# reference, where the `t` crossbar visibly meets the `h` shoulder. At gap zero
# the two one-pixel outlines share a column and the letters read as welded,
# which is the whole effect. Kept at -1 like every other weld; if the native
# art ever turns up, this is the value to check first.
& h t -1
